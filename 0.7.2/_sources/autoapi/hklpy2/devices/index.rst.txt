devices
=======

.. py:module:: hklpy2.devices

.. autoapi-nested-parse::

   Import: ``hklpy2.devices``

   Ophyd device construction helpers for |hklpy2|.

   These utilities are called during diffractometer creation to build ophyd
   ``Component`` and ``Device`` objects dynamically from axis specifications
   and factory configurations.

.. py:class:: VirtualPositionerBase(*, physical_name: str = '', **kwargs)

   .. container:: import-path

      Import: ``hklpy2.devices.VirtualPositionerBase``


   Bases: :py:obj:`ophyd.SoftPositioner`


   Base class for a diffractometer's virtual axis.

   This base class also serves as an example where the virtual axis is twice
   the value of the physical axis.  It is used as a Component of a
   'DiffractometerBase' definition.  The ``physical_name`` is the name of a
   sibling positioner attribute.

.. py:function:: describe_aux(diffractometer: object, name: str) -> dict

   .. container:: import-path

      Import: ``hklpy2.devices.describe_aux``


   Build a single ``axes.auxiliary_axes`` record for ``name``.

   Categorises the auxiliary into one of the schema-v2 categories:

   * ``"scalar"`` — a plain :class:`~ophyd.PositionerBase` (the historic
     default; the round-tripped simulator stand-in is an
     :class:`~ophyd.SoftPositioner`).
   * ``"pseudo_positioner"`` — a nested
     :class:`~ophyd.pseudopos.PseudoPositioner`; sub-axis names are
     recorded as ordered ``pseudos`` / ``reals`` lists.  ``class`` /
     ``module`` are advisory metadata only — never imported by hklpy2 on
     restore.

.. py:function:: dynamic_import(full_path: str) -> type

   .. container:: import-path

      Import: ``hklpy2.devices.dynamic_import``


   Import the object given its import path as text.

   Motivated by specification of class names for plugins
   when using ``apstools.devices.ad_creator()``.

   EXAMPLES::

       klass = dynamic_import("ophyd.EpicsMotor")
       m1 = klass("gp:m1", name="m1")

       creator = dynamic_import("hklpy2.diffract.creator")
       fourc = creator(name="fourc")

   From the `apstools <https://github.com/BCDA-APS/apstools>`_ package.


.. py:function:: make_aux_pseudo_positioner_class(name: str, pseudos: Sequence[str], reals: Sequence[str]) -> type

   .. container:: import-path

      Import: ``hklpy2.devices.make_aux_pseudo_positioner_class``


   Build a synthetic :class:`~ophyd.pseudopos.PseudoPositioner` subclass
   with the given sub-axis names.

   The resulting class is **structural only**: ``forward()`` and
   ``inverse()`` return zeros for every sub-axis.  Its purpose is to
   let downstream code (printers, plan inspection, etc.) traverse the
   same component tree the original device exposed.


.. py:function:: make_component(call_name: Any, *args: Any, **kwargs: Any) -> ~ophyd.Component

   .. container:: import-path

      Import: ``hklpy2.devices.make_component``


   Create an :class:`~ophyd.Component` for a custom ophyd Device class.

   ``call_name`` may be either a dotted import path (``str``) or an
   already-resolved callable (``type``).  The callable form is used by
   :func:`hklpy2.run_utils.simulator_from_config` when restoring a
   nested ``PseudoPositioner`` auxiliary whose synthetic stand-in class
   is built at runtime and therefore cannot be addressed by an import
   path.

   .. versionchanged:: 0.7.0
      Accept a callable in addition to a dotted import-path string.
      See :issue:`388`.
